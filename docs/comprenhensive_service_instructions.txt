## Part 1: Research & The Ultimate Nextcloud + App Combination for GutfitOS

The objective of GutfitOS is to provide each user with a sovereign, secure, and intelligent personal wellness environment. Nextcloud serves as the ideal foundation due to its open-source nature, robust API, extensive app ecosystem, and strong focus on data privacy and self-hosting. The "ultimate" combination involves selecting and configuring Nextcloud apps that directly support the core pillars of Gutfit: **Precision Nutrition, Adaptive Movement, Resilient Mindset,** and **Personalized Coaching/Community.**

### Core Nextcloud Apps for GutfitOS

The following apps are categorized by their primary function within the GutfitOS ecosystem. This list prioritizes stability, features relevant to wellness data management, and integration potential.

### Justification for App Selection

*   **Forms & Tables:** These are critical for moving beyond simple file storage into structured health data collection. **Forms** is excellent for user-friendly data entry, while **Tables** (once stable) offers more powerful data organization and querying capabilities, potentially serving as a lightweight personal health database for each user within their sovereign space. Starting with Forms is pragmatic due to its stability.
*   **Notes:** Offers a flexible, rich-text environment for journaling, which is a cornerstone of the Resilient Mindset pillar. Its versioning feature allows users to track their thought processes and progress.
*   **Tasks & Calendar:** Essential for habit formation, program adherence, and managing the various components of a holistic health plan (workouts, meal prep, mindfulness, coaching calls).
*   **Talk, Circles & Group Folders:** Provide a secure, integrated communication and collaboration platform, reducing reliance on external, less secure, or non-sovereign tools. This is vital for the Personalized Coaching and Community pillars.
*   **OpenID Connect Login:** Non-negotiable for a seamless and secure user experience across the entire Gutfit platform, ensuring GutfitOS is just one integrated part of the ecosystem, not a siloed login.

### Integrations with Other Gutfit Systems

1.  **Keycloak (Authentication & Authorization):**
    *   **Mechanism:** Nextcloud's "OpenID Connect Login" app.
    *   **Flow:**
        1.  User attempts to access GutfitOS (either via web or client app).
        2.  GutfitOS (Nextcloud) redirects to Keycloak for authentication.
        3.  User authenticates with Keycloak.
        4.  Keycloak redirects back to GutfitOS with an OIDC token.
        5.  Nextcloud validates the token and logs the user in, creating a local Nextcloud account if one doesn't exist (auto-provisioning) and mapping Keycloak groups to Nextcloud groups if configured.
    *   **Benefit:** Single sign-on across the entire Gutfit platform. Centralized user management and security policies.

2.  **PayloadCMS (Content Delivery):**
    *   **Mechanism:** Client App (EasyAppy) or a custom GutfitOS Nextcloud app.
    *   **Flow:**
        1.  PayloadCMS manages all content (articles, recipes, program details, video links).
        2.  The Gutfit Client App fetches relevant content from PayloadCMS.
        3.  User can choose "Save to GutfitOS" from the client app.
        4.  The client app then uploads this content (e.g., a PDF of a personalized plan, a recipe) to the appropriate folder in the user's GutfitOS instance via Nextcloud's WebDAV or API.
    *   **Benefit:** Users can build a personal library of curated Gutfit content within their sovereign space.

3.  **Moodle (Structured Learning):**
    *   **Mechanism:** User-driven saving or potentially a future Moodle-Nextcloud integration app.
    *   **Flow:**
        1.  Users access courses in Moodle.
        2.  They can save their notes, assignments, or important course materials to their `05_Learning/` folder in GutfitOS.
        3.  (Future) An app could allow Moodle to push specific resources directly to a user's GutfitOS.
    *   **Benefit:** Centralized repository for all learning-related materials.

4.  **AnythingLLM (AI Assistant):**
    *   **Mechanism:** A secure backend service that AnythingLLM can call, authenticated via Keycloak, to access user data from GutfitOS with explicit user consent.
    *   **Flow:**
        1.  User interacts with the AI Assistant in the Gutfit Client App.
        2.  AI Assistant (AnythingLLM) needs data to provide insights (e.g., "How has my sleep been this week?").
        3.  AnythingLLM makes a request to the GutfitOS Data Access Service.
        4.  This service, using a trusted Keycloak client token, authenticates and then, using Nextcloud's server-side APIs (e.g., `occ` commands, direct DB queries with extreme caution and abstraction, or future Nextcloud APIs for app data), retrieves the relevant data (e.g., from Forms submissions or Notes).
        5.  The data is returned to AnythingLLM, which then formulates a response for the user.
    *   **Benefit:** Enables the AI to provide truly personalized insights based on the user's sovereign data. **Crucially, this service must be built with extreme care for security, privacy, and explicit user consent.**

5.  **Wger / Mealie (External Fitness/Nutrition Trackers):**
    *   **Mechanism:** User-driven export/import or potential future integrations if these tools are self-hosted by Gutfit and offer APIs.
    *   **Flow:**
        1.  User tracks workouts in Wger or meals in Mealie.
        2.  User exports data (e.g., CSV) from Wger/Mealie.
        3.  User uploads this CSV to their `06_Trackers/` folder in GutfitOS.
        4.  (Future) If Gutfit self-hosts Wger/Mealie and they offer APIs, the GutfitOS Data Access Service could potentially fetch this data directly if the user authorizes it.
    *   **Benefit:** Allows users to consolidate data from various specialized tools into their sovereign GutfitOS.

## Part 2: Foundational Implementation - Small Steps from a Fresh Server

This section outlines the absolute initial, fundamental steps to get a basic GutfitOS (Nextcloud) instance running. This assumes a single server to start with.

### Phase 1: Server & Docker Environment

1.  **Provision a Server:**
    *   Choose a Linux distribution (e.g., Ubuntu 22.04 LTS).
    *   Perform initial server hardening: update system, configure firewall (UFW), create a non-root user with `sudo` access, set up SSH key-based authentication.
    *   Install Docker and Docker Compose.
        ```bash
        # Add Docker's official GPG key:
        sudo apt-get update
        sudo apt-get install ca-certificates curl
        sudo install -m 0755 -d /etc/apt/keyrings
        sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
        sudo chmod a+r /etc/apt/keyrings/docker.asc

        # Add the repository to Apt sources:
        echo \
          "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
          $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
          sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

        # Install Docker Engine, CLI, and Compose plugin:
        sudo apt-get update
        sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
        ```
    *   Add your user to the `docker` group: `sudo usermod -aG docker $USER`. Log out and back in for changes to take effect.

### Phase 2: Deploy Core GutfitOS (Nextcloud) Instance

1.  **Create Project Directory and `docker-compose.yml`:**
    *   Create a directory for your GutfitOS deployment, e.g., `/opt/gutfit-os`.
    *   Inside this directory, create a `docker-compose.yml` file. This example uses PostgreSQL and Redis, which are recommended for production.

    ```yaml
    # /opt/gutfit-os/docker-compose.yml
    version: '3.8'

    services:
      gutfitos-app:
        image: nextcloud:latest # Use a specific version tag for production
        container_name: gutfitos-app
        restart: unless-stopped
        ports:
          - "8080:80" # Access Nextcloud on port 8080 of your server
        volumes:
          - gutfitos_data:/var/www/html
          - ./custom-config:/var/www/html/config # Mount for custom config.php
        environment:
          - POSTGRES_HOST=gutfitos-db
          - POSTGRES_DB=nextcloud # Database name
          - POSTGRES_USER=nextcloud_user # Database user
          - POSTGRES_PASSWORD=your_strong_nextcloud_db_password # IMPORTANT: Change this
          - REDIS_HOST=gutfitos-redis
          - NEXTCLOUD_ADMIN_USER=admin # Initial Nextcloud admin user
          - NEXTCLOUD_ADMIN_PASSWORD=your_strong_nextcloud_admin_password # IMPORTANT: Change this
          - NEXTCLOUD_TRUSTED_DOMAINS=your-gutfitos-domain.com # If using a domain
          - OVERWRITEPROTOCOL=https # If using a reverse proxy for SSL
          - OVERWRITEHOST=your-gutfitos-domain.com # If using a domain
          - TRUSTED_PROXIES=172.18.0.0/16 # Adjust if your Docker network differs
        depends_on:
          - gutfitos-db
          - gutfitos-redis
        networks:
          - gutfitos-network

      gutfitos-db:
        image: postgres:15-alpine
        container_name: gutfitos-db
        restart: unless-stopped
        volumes:
          - gutfitos-db-data:/var/lib/postgresql/data
        environment:
          - POSTGRES_DB=nextcloud
          - POSTGRES_USER=nextcloud_user
          - POSTGRES_PASSWORD=your_strong_nextcloud_db_password # IMPORTANT: Change this
        networks:
          - gutfitos-network

      gutfitos-redis:
        image: redis:alpine
        container_name: gutfitos-redis
        restart: unless-stopped
        volumes:
          - gutfitos-redis-data:/data
        networks:
          - gutfitos-network

    volumes:
      gutfitos_data:
      gutfitos-db-data:
      gutfitos-redis-data:

    networks:
      gutfitos-network:
        driver: bridge
    ```
    *   **Crucial:** Replace placeholder passwords with strong, unique values.

2.  **Create `custom-config` directory and a basic `config.php` override:**
    *   `mkdir -p /opt/gutfit-os/custom-config`
    *   Create `/opt/gutfit-os/custom-config/custom.config.php`:

    ```php
    <?php
    $CONFIG = [
      'instanceid' => 'oc' . bin2hex(random_bytes(4)), // Generate a unique instance ID
      'secret' => 'your_very_long_random_secret_for_nextcloud', // Generate a strong secret
      'datadirectory' => '/var/www/html/data',
      'dbtype' => 'pgsql',
      'dbhost' => 'gutfitos-db',
      'dbname' => 'nextcloud',
      'dbuser' => 'nextcloud_user',
      'dbpassword' => 'your_strong_nextcloud_db_password', // IMPORTANT: Change this
      'dbtableprefix' => 'oc_',
      'memcache.local' => '\\OC\\Memcache\\Redis',
      'memcache.distributed' => '\\OC\\Memcache\\Redis',
      'memcache.locking' => '\\OC\\Memcache\\Redis',
      'redis' => [
        'host' => 'gutfitos-redis',
        'port' => 6379,
      ],
      'overwrite.cli.url' => 'https://your-gutfitos-domain.com', // For occ commands if using a domain/SSL
      'overwritehost' => 'your-gutfitos-domain.com',
      'overwriteprotocol' => 'https',
      'default_phone_region' => 'US', // Adjust as needed
      'default_language' => 'en',
      'default_locale' => 'en_US',
      'force_language_for_guests' => true,
      'knowledgebaseenabled' => true,
      'allow_user_to_change_display_name' => false,
      'lost_password_link' => 'disabled', // If using Keycloak SSO primarily
      'onlyoffice' => false, // Unless you plan to use OnlyOffice
      'loglevel' => 2, # 0 = DEBUG, 1 = INFO, 2 = WARN, 3 = ERROR
      'logdateformat' => 'F d, Y H:i:s',
      'logfile' => '/var/www/html/data/nextcloud.log',
      'log.condition' => [
        'apps' => ['admin_audit'], // Log admin_audit app events
      ],
    ];
    ```
    *   Generate strong values for `instanceid` and `secret`. You can use `openssl rand -hex 16` for instanceid and `openssl rand -base64 32` for secret.

3.  **Start Nextcloud:**
    *   Navigate to `/opt/gutfit-os`.
    *   Run `docker-compose up -d`.
    *   Monitor logs: `docker-compose logs -f gutfitos-app`.

4.  **Initial Nextcloud Web Setup:**
    *   Access Nextcloud via `http://your_server_ip:8080`.
    *   You should see the Nextcloud setup screen.
    *   Create an admin account (the `NEXTCLOUD_ADMIN_USER` and `NEXTCLOUD_ADMIN_PASSWORD` from `docker-compose.yml` will pre-fill this if the database was empty).
    *   Data folder and database information should already be filled by environment variables.
    *   Click "Install & Finish".

5.  **Basic Post-Installation Hardening via `occ` commands:**
    *   Execute `occ` commands inside the `gutfitos-app` container:
        ```bash
        docker exec -u www-data gutfitos-app php occ maintenance:update:htaccess
        docker exec -u www-data gutfitos-app php occ db:add-missing-indices
        docker exec -u www-data gutfitos-app php occ db:convert-filecache-bigint
        docker exec -u www-data gutfitos-app php occ db:convert-filecache
        docker exec -u www-data gutfitos-app php occ app:update --all
        ```
    *   Check Security & Setup Warnings in Nextcloud Admin UI and address them. Common ones include:
        *   Set up memory caching (Redis is configured above).
        *   Set up OPcache (PHP OPcache extension needs to be installed on the host system or within the Nextcloud container if using a custom Dockerfile).
        *   Default phone region (set in `custom.config.php`).
        *   Add missing indexes (command above).
        *   Configure SMTP mail (set environment variables in `docker-compose.yml` or via Admin UI).

### Phase 3: Install and Configure Core Nextcloud Apps

1.  **Access Nextcloud Admin Panel:** As the admin user, go to your user icon -> Administration settings -> Apps.
2.  **Install Apps:** Search for and install the following core apps:
    *   Notes
    *   Tasks
    *   Calendar
    *   Contacts
    *   Talk
    *   Forms
    *   Circles
    *   Group Folders
    *   Deck (Optional)
    *   PDF Viewer (Optional)
    *   OpenID Connect Login
3.  **Configure OpenID Connect Login:**
    *   In Nextcloud Admin settings, go to Administration -> Security -> OpenID Connect Login.
    *   Add a new OIDC provider (e.g., "Gutfit Keycloak").
    *   You will need Client ID, Client Secret, and Discovery URL from your Keycloak setup.
    *   Ensure "Disable auto creation of new users" is **unchecked** if you want Keycloak users to be automatically provisioned in Nextcloud.
    *   Test the configuration.

### Phase 4: Manual User Onboarding & Folder Structure Test

1.  **Create a Test User in Keycloak:** If not already done, create a user in your Keycloak realm (e.g., `testuser@gutfit.co`).
2.  **Log in as Test User to GutfitOS:**
    *   Go to your GutfitOS URL (`http://your_server_ip:8080`).
    *   Click "Log in with [Your Keycloak Provider Name]".
    *   Authenticate with your Keycloak test user credentials.
    *   A new Nextcloud account for `testuser` should be created automatically, and they should be logged in.
3.  **Create Sample Folders:**
    *   As the test user, manually create the folder structure outlined in Part 1 (e.g., "My Gutfit Journey" with subfolders).
    *   Test creating a Note, a Task, a Calendar event, and a Form.
    *   This helps you understand the user experience and refine the folder structure template.

### Phase 5: Set Up Reverse Proxy & SSL (Highly Recommended)

1.  **Choose a Reverse Proxy:** Caddy (easy with automatic HTTPS) or Nginx.
2.  **Configure Proxy:**
    *   The proxy should handle incoming traffic on ports 80/443.
    *   It should forward requests to `gutfitos-app` container on port 8080.
    *   It should terminate SSL and set appropriate headers (e.g., `X-Forwarded-Proto`, `X-Forwarded-For`).
    *   Ensure your `OVERWRITEPROTOCOL`, `OVERWRITEHOST`, and `TRUSTED_PROXIES` settings in `custom.config.php` are correct for your proxy setup.
3.  **Update DNS:** Point your `your-gutfitos-domain.com` to your server's IP address.
4.  **Verify:** Access GutfitOS via `https://your-gutfitos-domain.com`.

These small steps establish a foundational, single-node GutfitOS (Nextcloud) instance. From here, you can iteratively add more sophisticated features, integrations (especially the AI data access service), and scale the infrastructure as needed. The "ultimate" configuration is a journey, but these steps provide a solid and practical starting point.
